# 17 — v2.11 多笔委托篮 (multi-order basket)

## 1. 一句话 + Why

模拟盘从"每周只能下一笔单"升级为"一周可下多笔委托,确认前可逐笔撤回"。这是 v2.7 真实化交易规则的
自然收口:真实账户从不限制一周只交易一次 —— 玩家应在提交前自由增删委托,确认后一次性成交。

## 2. 现状问题

v2.4 起的 `resolveOrder`/`executeOrder` 是**单笔**入口,`InvestPanel` 每周只能"选一个品种 + 一个方向 +
一个金额"直接提交。用户反馈:每周只能交易一次,不符合真实交易习惯;且确认前没有反悔机会。

## 3. 设计决策(关键取舍)

| 决策 | 取舍 |
|---|---|
| **委托篮 = `Record<assetId, DraftOrder>`** | 一个品种一笔委托(key 去重),再次委托 = 更新;不允许同一品种两笔,消除歧义 |
| **确认前可撤回** | 委托是 React 本地状态,`加入委托`/`✕ 取消`/`清空` 全部在本地完成,**不产生任何成交**,只有点 `确认 N 笔下单` 才调用 `invest(orders)` |
| **空篮 = 不操作** | `invest([])` 走 hold;`.no-invest-button` 保留为"一键不操作"(既有探针契约) |
| **主按钮保留单笔快速路径** | 篮空时主按钮 = `确认买入/卖出 品种 ¥金额`(原单笔契约,showcase/marathon 探针零改动);篮非空时 = `确认 N 笔下单` |
| **canonical 成交顺序 = ASSETS 数组序** | 成交顺序**不依赖用户添加顺序**,而是按产品固有顺序(money_fund→bond→gold→index_fund→a_index→hk_index→btc);同一篮子 → 同一结果,现金不足时"靠后的不足额成交"可预期 |
| **running account 贯穿** | 逐笔成交时,后一笔看到前一笔后的 account(现金被扣、持仓被改),所以 T+1 门与现金钳制都对**中间态**生效,不会被"先卖后买"的顺序逃逸 |
| **`side` 加 `'mixed'`** | 同一周既买又卖 → `mixed`;纯买/纯卖/纯拦截/空篮分别归 `buy`/`sell`/`sell`或`buy`/`hold` |
| **不新增随机源** | `resolveOrders`/`executeOrder` 永不调用 `rand()`;种子确定性契约不破(rand 只在 invest 入场的 `buildMarketView` 与 `finishCoach` 微觉醒里消耗) |

## 4. 数据契约(types.ts)

```ts
type DraftOrder = { assetId: string; side: 'buy' | 'sell'; amount: number }
type BlockedOrder = { assetId: string; side: 'buy' | 'sell'; reason: string }

interface InvestmentResult {
  // …原有标量保留(units/price/amount/fee/blockedReason 作为兼容聚合)
  side: 'buy' | 'sell' | 'hold' | 'mixed'
  fills: OrderResult[]      // 实际成交的每一笔(units>0 才计入)
  blocked: BlockedOrder[]   // 被 T+1 拦截的每一笔,内联原因
  // units = Σ fills.units · amount = Σ fills.amount · fee = Σ fills.fee · price = first fill
}
```

## 5. 关键实现

- `invest.ts`:`resolveOrders(accountBefore, orders: DraftOrder[], turn1Based, shockPct?)`
  — 过滤 `amount>0` 且有限的委托 → 按 ASSETS 序排序 → 逐笔 `executeOrder`(running account)+ T+1 门
  (`heldPos.boughtTurn === turn1Based` 拦截卖单)+ 买单 `boughtTurn=turn1Based` 盖章 → 循环后一次性算
  `openValue`/`totalValue`/`weekPnlAbs`/`totalPnlAbs`。`resolveOrder` 变薄包装,委托 `resolveOrders`。
- `Simulation.ts`:`makeInvestment(state, orders)` 用**同一 orders** 对 `state.paper` 与 `state.altPaper`
  (平行命运孪生)各跑一次 `resolveOrders`;alt 只暴露 `investmentPnlAbs`(名义镜像,非逐笔成交)。
- `store.ts`:`invest: (orders: DraftOrder[]) => void`;`resolveOrders` 加入 `__sim.checks`。
- `InvestPanel.tsx`:委托篮 UI(见 §6)。
- `AICoachPanel.tsx`:结果卡逐笔渲染 `fills.map` → `.invest-fill-line`,`blocked.map` → `.invest-blocked`,
  底部 `.invest-result-totals` 汇总本周/总盈亏。
- `ParallelFateCard.tsx`:单笔沿用"买入/卖出 N 份 @ ¥price",多笔 = `本周 N 笔交易`,全拦截 = `被规则拦截 · 未成交`,
  `mixed` 加 `fate-investment-mixed` 修饰。

## 6. 委托篮 UI

- 每个品种的 `加入委托`(`.add-draft-button`,已入篮则显示 `更新委托`)把当前选中品种/方向/金额写入篮。
- `.basket` 列表按 canonical 产品序展示,每行:品种 + 买入/卖出 + 金额 + `✕`(`.basket-remove`)。
- `.basket-head` 显示 `共 N 笔` + `清空`;买入合计超可用资金时 `.basket-warn` 提示"按产品顺序依次成交"。
- 主按钮:篮空 → 单笔 `确认买入/卖出`;篮非空 → `确认 N 笔下单`。`.no-invest-button` 一键不操作。

## 7. 边界

- **T+1**:同一周买→卖同一品种,卖单被拦截为 `blocked`(金额 0,不成交),`side` 归 `sell` 或 `mixed`。
- **现金钳制**:canonical 顺序靠后的买单在现金不足时自动缩量或 0 成交(`executeOrder` 现有钳制)。
- **同一品种去重**:key = assetId,后委托覆盖先委托。
- **旧 save 兼容**:`boughtTurn` 缺省 `undefined` = 可卖(向后兼容)。

## 8. 验证

`resolveOrders` 纯函数 pins 落在 `scripts/showcase.mjs`(空篮=hold / canonical 顺序不敏感 / mixed 两笔 /
T+1 拦截 / Σ 聚合);`scripts/basket-probe.mjs` 驱动 UI(两笔入篮 → 撤一笔 → 确认 1 笔成交;两笔 → 确认 2 笔成交)。
