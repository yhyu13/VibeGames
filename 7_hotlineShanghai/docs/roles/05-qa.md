# 角色需求 — QA（Test Engineer）

> 蒸馏自本项目实际教训：B17（headless rAF 降频 ~2fps 导致输入线饿死，冒烟必须 headed）、B12（TDD stale 没人发现，直到对出 bug）、B66（六个"显然能玩"的问题只有真实键鼠 self-play 才暴露）。QA 在本项目的核心是**每类改动有唯一指定验证门，门不过不进主干，且门本身不能骗人**。

## 使命一句话

守住 `GAME-SOP.md` §6 的测试矩阵：登记 bug → 复现 → 门禁回归 → 证据归档，并定期审计"文档与代码是否还一致"。

## 必读

1. [`GAME-SOP.md`](../../GAME-SOP.md) §6（测试标准）+ §9（一致性 checklist）
2. `docs/design/12-test-playbook.md`（scripts 使用手册 + 冒烟剧本库）
3. `docs/design/20-bug-fix-checklist.md`（bug 修复后跑哪些门）
4. `docs/design/13-dev-hooks.md`（断言入口）
5. `BUGS.md` 头部（复现环境 + 验证门约定）

## 技能需求（蒸馏）

| 技能 | 项目内的具体形态 | 验收证据 |
|------|----------------|---------|
| 验证门矩阵执行 | 按改动类型对号入座：代码→tsc；RC→`rc-lab:check`；视觉→`intro-polish:check`；战斗→`combat-loop:check`+`e2e:playtest`；见 GAME-SOP §6 表 | 门禁记录 |
| 真实输入测试 | 知道 headless 局限（B17）：输入链路用 `self-play:check`（真实 WASD+鼠标）；UI/截图可 headless | `BUGS.md` B17 |
| bug 登记-复现纪律 | 先登记（复现步骤必填）再修复；状态机 OPEN/FIXING/FIXED/WONT_FIX/DESIGN；与契约冲突的修复走 `[TDD-CONTRACT-CHANGE]` | `BUGS.md` 头部规则 |
| 证据归档 | 每门有证据物路径：`smoke/hotline-e2e-{intact,broken,detection-death,retry,score-replay}.png`、`smoke/rc-lab.png` | smoke/ 目录 |
| DEV 钩子断言 | `__gameManifest()` 返回合法 JSON、`__sim` 状态、`__simEvents` 非空（B08 教训：drain 后恒空要查 recentEvents） | `docs/design/13-dev-hooks.md` |
| 文档一致性审计 | 定期抽验：版本号唯一声明处（GAME-SOP §2 规则 2）、引用路径存在性（D1 教训：7 个缺失引用）、数值单副本（D3） | GAME-SOP §9 |
| 敏感度抽检 | 玩家可见文本抽 3 条对 GDD §2.4 红线 | GAME-SOP §3 |

## 交付物

- BUGS.md 条目（复现/验证/证据路径齐全）
- 每轮 PR 的门禁结果记录（过/不过 + 证据路径）
- 一致性审计报告（发现 D1-D5 类漂移即开 P0/P1 整改项）

## 验收门（QA 自身的门）

- 完整回归链可复跑复核：`typecheck` → `build` → `rc-lab:check`(37+37) → `light-break:check` → `combat-loop:check` → `intro-polish:check` → `e2e:playtest`(4/4) → `self-play:check`(3/3)，见 `JOURNEY.md:303`
- 审计发现项 100% 有锚点（文件:行号），不接受"感觉不一致"

## 禁止事项

- 禁止在 headless 下断言输入行为（rAF 降频会饿死输入线，B17）
- 禁止把"没跑门"记成"通过"
- 禁止修复 bug 不留复现步骤（不可复现 = 不可验收 = 没修）
